Before tagging, list the features not yet marked released and make someone look once. Status changes lag shipping whenever they happen in a later pull request, which is what makes a release date derived from them wrong. This goes at the cause rather than modelling the symptom. Something chocks runs, so it works the same before you tag and from a workflow calling it. A GitHub app could surface it instead, but installing a service is the opposite of what chocks is for.
